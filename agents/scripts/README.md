# Agent scripts

Bash scripts used as benchmark agents through the repository-local Harbor
custom agent `bash_script_agent.agent:BashScriptAgent`.

## Usage in a scenario

```yaml
agent:
  name: bash_script_agent.agent:BashScriptAgent
  # Path to the script, relative to the repository root. `HarborRunner`
  # validates that the file exists before invoking Harbor and passes its
  # absolute path to `harbor run --model`, which the custom agent reads to
  # decide what to upload and run inside the container.
  model: agents/scripts/example-agent.sh
```

Each distinct script behaves like a distinct agent: create one file per agent
variant you want to benchmark.

## Script contract

The custom agent uploads the script into the task container (line endings
normalized to LF) and runs it as `bash /installed-agent/agent.sh`:

- **User:** the container's agent user (non-root).
- **Working directory:** `/workspace` — the sandbox repository freshly cloned
  from the GitHub sandbox, with `git` and headlessly authenticated `gh`
  available.
- **Instruction:** the task prompt (what the issue asks for) is exported in
  the `INSTRUCTION` environment variable.
- **Exit code:** exit `0` only when the agent is done; any non-zero exit
  fails the trial with `NonZeroAgentExitCodeError`. The scenario's separate
  verifier (`tests/test.sh` generated by `HarborRunner`) still decides the
  final reward, so a confident agent does not grade itself.
- **Line endings:** keep LF in the repository; CRLF is normalized on upload,
  but LF-native scripts avoid surprises with shebangs and diffs.

## Failure output

> **xaa agent state:** `xaa.sh` runs with `X_AEON_AGENTS_CONFIG`
> pointing at `/etc/x_aeon_agents.rb` (baked into the task image),
> which sets `data_dir '/logs/agent/xaa'`. That path is a Harbor
> bind mount, so session state is live on the host at
> `<trial>/agent/xaa/` during the run — handy for
> debugging — while staying out of `/workspace`, so Harbor's
> whole-`/workspace` artifact upload into the separate verifier never
> sees the deep `sessions/...` tree that breaks `docker compose cp` on
> Windows.

Harbor caps exec output at 1000 chars inside `NonZeroAgentExitCodeError`
messages (the `... [N chars truncated] ...` you see in `exception.txt` and
`result.json`). `BashScriptAgent` compensates two ways:

- Full transcript: the script runs as
  `bash /installed-agent/agent.sh 2>&1 | tee /logs/agent/agent-output.log`
  (exit code preserved via `PIPESTATUS[0]`), and Harbor syncs
  `/logs/agent/` to `<trial>/agent/` on the host even on failure. Read the
  untruncated output there first.
- Raised message cap: `_truncate_output` keeps Harbor's head+tail format
  but defaults to 100000 chars (`BashScriptAgent.DEFAULT_MAX_OUTPUT_CHARS`),
  overridable via the `BASH_SCRIPT_AGENT_MAX_OUTPUT` env var (agent
  `extra_env` or host env). `exception.txt` therefore stays complete for
  realistically sized output.

## Adding a new agent script

1. Copy `example-agent.sh` to a new file next to it (or any path in the repo).
2. Implement the agent logic (call a model CLI, apply patches, ...).
3. Reference the script from a scenario's `agent.model` as shown above.
